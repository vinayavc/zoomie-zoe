# Zoomie Zoe as an installable offline web app (PWA)

## The dev rule
- **localhost = dev, no service worker.** Code edits always show up on reload. If a service worker was left over on a `localhost` origin, `pwa.js` unregisters it and deletes its caches on the next load.
- **127.0.0.1 or the deployed site = PWA.** The service worker registers and the game is cached for offline play.
- The Chrome extension (`chrome-extension:`) and `file://` pages never register a service worker.

## Files
| File | Job |
|---|---|
| `src/manifest.webmanifest` | Name, icons, `display: standalone`, `orientation: portrait`, colors. `start_url` and `scope` are `./`, so it works from a GitHub Pages sub-path. |
| `src/sw.js` | The service worker. It has a single `CACHE_VERSION` constant and a `FILES` list. |
| `src/js/pwa.js` | Registers `sw.js` after page load. It's loaded by its own `<script type="module">` tag. |
| `src/icons/192.png`, `512.png` | Manifest icons (`purpose: any`, transparent padding like the 128 store icon). |
| `src/icons/maskable-512.png` | Android adaptive icon. It's opaque paper, and Zoe's disk sits inside the 40%-radius safe circle. |
| `src/icons/180.png` | `apple-touch-icon`. It's opaque because iOS fills transparent areas with black. |
| `<head>` of `src/index.html` | Manifest link, `theme-color`, apple-touch-icon, favicon, and the `mobile-web-app-capable`, `apple-mobile-web-app-*` meta tags. |

- Colors come from `src/js/art/palette.js`: `theme_color` and `background_color` are `P.indigo` (#3F4A73), which is close to the letterbox color in `style.css`.
- Icons are drawn by `store/tools/icon-maker.html` (the `PWA_SIZES` block). To regenerate them, serve the project root and open that page. The existing 16/32/48/128 icons were not changed.
- The extension manifest (`src/manifest.json`) is separate and untouched.

## How the service worker works
1. **Install:** it downloads every file in `FILES` into the cache `zoomie-zoe-<CACHE_VERSION>`, bypassing the HTTP cache. If any file is missing, the install fails and the old version keeps running.
2. **Activate:** it deletes every other `zoomie-zoe-*` cache, then takes control of open pages (`skipWaiting` + `clients.claim`).
3. **Fetch** (same origin only):
   - **Pages** are network-first. If the network fails or takes more than 4 s, the cached `index.html` is used.
   - **Everything else** (JS, CSS, icons, manifest) uses stale-while-revalidate: it's served from the cache instantly and refreshed in the background.

The art and sound are generated by code, so the cached files are the whole game. Nothing remote is loaded.

## Every release: bump the version
1. In `src/sw.js`, change `const CACHE_VERSION = 'v1';` to `'v2'` (then `'v3'`, and so on).
2. **If you added, renamed or removed a file, update `FILES` too.** This includes the upcoming `js/themes/*.js` files. A theme module that isn't listed only works offline after it has been loaded once online. To list everything the game ships, run:
   `cd src && find . -name '*.js' -not -name sw.js | sort`
3. Publish. On a player's next visit, the browser sees that `sw.js` changed, installs the new cache, and deletes the old one. The new code runs from the reload after that. Because pages are network-first, an online visit picks up a new `index.html` immediately.

## Testing offline (Chrome or Edge on a laptop)
1. Open `http://127.0.0.1:8742/` (not `localhost`). Wait a few seconds.
2. DevTools → **Application** → Service workers: `sw.js` should be *activated and running*. Under Cache storage, `zoomie-zoe-v1` should list about 33 files. The **Manifest** panel should show the name, the three icons and no installability errors.
3. DevTools → **Network** → set throttling to **Offline**. Reload and play a round. It should work fully.
4. Turn Offline off again.

On a phone, load the deployed site once, switch to airplane mode, and open the installed app.

### Dev tip: clean up after testing on 127.0.0.1
A service worker on `127.0.0.1:8742` serves cached code first, so your edits only appear one reload late. When you're done testing:
- DevTools → Application → **Storage** → **Clear site data**, or
- paste this into the console on that page:
  `(await navigator.serviceWorker.getRegistrations()).forEach(r => r.unregister()); for (const k of await caches.keys()) await caches.delete(k);`

For day-to-day work, use `http://localhost:8742/`, which never has a service worker.

## Installing
- **Android (Chrome):** open the site, then tap the ⋮ menu → **Install app** (or "Add to Home screen"). Chrome may also show an install banner after you've interacted with the page. The app opens full-screen in portrait with the maskable Zoe icon.
- **iPhone/iPad (iOS 16.4+):** in Safari (or Chrome, Edge or Firefox on iOS), tap **Share** → **Add to Home Screen**. The icon is `icons/180.png`. It opens standalone with no browser bars, and the status bar is translucent over the indigo letterbox. iOS never shows an install prompt, so Vinny should tell players about the Share step.
- **Desktop (Chrome/Edge):** use the install icon at the right end of the address bar, or ⋮ → **Cast, save and share** → **Install page as app**. Safari on macOS uses File → **Add to Dock**. Firefox desktop doesn't install PWAs, but the game still runs and caches offline there.

### iOS caveats
- Safari deletes a site's script-writable storage, including service worker caches **and the saved best score**, after 7 days of Safari use without a visit to that site. A home-screen app has its own counter that resets whenever the app is opened, so data shouldn't vanish while Vinny keeps playing. Weeks of not opening it can still mean the next launch needs the network once.
- Home-screen apps and Safari tabs have separate storage. A best score from the Safari tab doesn't carry over to the installed app.
- The `orientation` field isn't enforced on iOS. The game letterboxes in landscape anyway.

## Verified (Oct 11, 2026)
The checks ran in headless Chrome 152 against a scratch copy of the dev server on port 8744. The Claude browser pane can't fetch service-worker scripts: registration fails there with "unknown error", which is harmless and leaves only a console warning.
- The manifest is fetched and parsed. All three icons decode at the right sizes.
- `sw.js` activated with scope `http://127.0.0.1:8744/`, and the `zoomie-zoe-v1` cache held all 33 `FILES` with none missing.
- **Real offline test:** I killed the server and confirmed with curl that it was down, then opened a new tab. All 33 files came back 200 from the service worker with `cache: 'no-store'`, and `index.html` loaded and drew the game canvas (400×600, many colors).
- **Version bump:** I served `sw.js` with `v2` and called `update()`. Caches went from `[zoomie-zoe-v1]` to `[zoomie-zoe-v2]`, with 33 files.
- On a `localhost` origin with a leftover service worker, loading `index.html` removed it and its caches. A fresh profile on `127.0.0.1` registered through `pwa.js` alone.
- Not tested: an actual install prompt or install, a real phone, and the extension popup. In the popup, `pwa.js` returns early because the protocol is `chrome-extension:`.
